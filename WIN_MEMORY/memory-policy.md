# Memory Policy

## Purpose

`WIN_MEMORY` is the durable, human-readable memory layer for the project.

## Rules

- Prefer concise markdown entries over large prose blocks.
- Store stable facts, preferences, roles, and mission state here.
- Append new work-log entries instead of rewriting history.
- Keep one idea per file when the topic is naturally narrow.
- Do not store secrets, tokens, or transient runtime noise.
- When a file is missing, create it with starter content before writing to it.

## Writing Style

- Use plain language.
- Keep headings stable so automated tools can link to them.
- Make updates easy to review in git diffs.
